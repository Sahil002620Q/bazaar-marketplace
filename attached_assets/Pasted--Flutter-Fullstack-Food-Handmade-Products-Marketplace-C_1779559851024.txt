# Flutter Fullstack Food & Handmade Products Marketplace - Complete Specification

## Project Overview
Build a fullstack Flutter mobile application for buying and selling homemade food items (pickles, chawal badi, roohafza, etc.) and handmade products (woolen clothes, keychains, etc.). The platform supports dual marketplace models: traditional e-commerce orders and WhatsApp-based ordering with seller profiles.

---

## 1. TECH STACK & SETUP

### Frontend
- **Framework**: Flutter (latest stable)
- **Language**: Dart
- **State Management**: Riverpod 2.4+
- **UI Components**: Flutter Material 3 + Custom widgets
- **Authentication**: Google Sign-In + Firebase Auth
- **Local Storage**: Hive (encrypted)
- **API Client**: Dio with interceptors
- **Image Handling**: Cached Image Networks + Image Picker
- **Theme Management**: Provider + custom theme configuration
- **Animations**: Built-in Flutter + Lottie

### Backend
- **Runtime**: Node.js (Express.js 4.18+)
- **Language**: TypeScript
- **Database**: MongoDB 6.0+ (for flexibility)
- **Cache**: Redis (optional, for performance)
- **Authentication**: Firebase Admin SDK + JWT tokens
- **File Storage**: Firebase Cloud Storage or AWS S3
- **APIs**: RESTful JSON
- **Validation**: Zod schemas
- **WhatsApp Integration**: Twilio WhatsApp API / WhatsApp Business API

### Infrastructure
- **Hosting**: Firebase Functions or DigitalOcean/AWS (Express backend)
- **Database Hosting**: MongoDB Atlas (free tier available)
- **CI/CD**: GitHub Actions
- **Version Control**: Git + GitHub

## 3. DETAILED FEATURE SPECIFICATIONS

### 3.1 AUTHENTICATION FLOW

#### User Registration
1. **Login Screen**
   - Google Sign-In button (Material Design)
   - Minimal, dark theme by default
   - Shows "Continue with Google" CTA
   - Auto-fills email from Google account

2. **Post-Login: User Type Selection**
   - Button: "I'm a Buyer"
   - Button: "I'm a Seller (Requires Admin Approval)"
   - Buyers proceed to Home
   - Sellers proceed to Setup Screen

3. **Seller Setup Screen** (only for new sellers)
   - Full Name (required)
   - Phone Number (required, with validation)
   - Address (required, multi-line)
   - Shop Name (optional)
   - Payment Methods (checkboxes: Razorpay, COD, etc.)
   - Ordering Mode (radio: E-Commerce or WhatsApp)
   - WhatsApp Number (required if WhatsApp mode selected)
   - Submit button
   - State: "Pending Admin Approval" → wait for admin confirmation
   - Admin must mark account as "Seller" for access to selling features

#### Token Management
- Firebase JWT tokens stored in Hive
- Auto-refresh on token expiration
- Logout clears local storage

## 5. API SPECIFICATION

### Base URL
```
Production: https://api.foodmarketplace.com/api/v1
Development: http://localhost:5000/api/v1
```

### Authentication Header
```
Authorization: Bearer <JWT_TOKEN>
Content-Type: application/json
```

### Endpoints Overview

#### Auth Endpoints
```
POST   /auth/google-signin         (Google ID token → JWT)
POST   /auth/refresh-token         (Refresh expired JWT)
POST   /auth/logout                (Invalidate token)
GET    /auth/verify                (Check token validity)
```

#### User Endpoints
```
GET    /users/profile              (Get current user profile)
PUT    /users/profile              (Update user profile)
GET    /users/address              (Get saved addresses)
POST   /users/address              (Add new address)
PUT    /users/address/:id          (Update address)
DELETE /users/address/:id          (Delete address)
```

#### Product Endpoints
```
GET    /products                   (List all products, filters: category, search, sort, page)
GET    /products/:id               (Get product details)
GET    /products/seller/:sellerId  (Get products by seller)
POST   /products                   (Create product, seller only)
PUT    /products/:id               (Update product, seller only)
DELETE /products/:id               (Delete product, seller only)
```

#### Order Endpoints
```
POST   /orders                     (Create order - E-Commerce mode)
GET    /orders                     (Get user's orders with filters)
GET    /orders/:id                 (Get order details)
PUT    /orders/:id/status          (Update order status, seller only)
PUT    /orders/:id/cancel          (Cancel order)
GET    /orders/history             (Order history with pagination/filters)
```

#### Seller Endpoints
```
GET    /sellers/dashboard          (Seller dashboard data)
GET    /sellers/:id                (Get seller profile)
PUT    /sellers/:id                (Update seller info)
GET    /sellers/:id/settings       (Get seller settings: mode, payment methods)
PUT    /sellers/:id/settings       (Update seller settings)
GET    /sellers/:id/orders         (Get seller's orders with filters)
GET    /sellers/:id/sales-history  (Sales analytics with filters)
PUT    /sellers/approve/:id        (Admin endpoint: approve seller)
```

#### WhatsApp Integration Endpoints
```
POST   /whatsapp/send-message      (Send pre-filled message to seller's WhatsApp)
GET    /whatsapp/message-template  (Get formatted order message)
```

### Error Response Format
```json
{
  "success": false,
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Invalid input",
    "details": {}
  }
}
```

### Success Response Format
```json
{
  "success": true,
  "data": {},
  "pagination": {
    "page": 1,
    "limit": 20,
    "total": 150
  }
}
```

### 8.4 WhatsApp Integration
```dart
// whatsapp_service.dart
class WhatsAppService {
  static Future<void> sendOrderMessage({
    required String sellerPhone,
    required List<CartItem> items,
    required String userAddress,
    required String userName,
    required String userPhone,
    required double totalPrice,
  }) async {
    final message = _formatOrderMessage(
      items: items,
      userAddress: userAddress,
      userName: userName,
      userPhone: userPhone,
      totalPrice: totalPrice,
    );
    
    final encodedMessage = Uri.encodeComponent(message);
    final whatsappUrl = "https://wa.me/$sellerPhone?text=$encodedMessage";
    
    if (await canLaunch(whatsappUrl)) {
      await launch(whatsappUrl);
    }
  }
  
  static String _formatOrderMessage({...}) {
    return '''Hello, I would like to place an order:

Items:
${items.map((e) => '- ${e.productName} (Qty: ${e.quantity}) - ₹${e.price}').join('\n')}

Total: ₹$totalPrice

Delivery Address:
$userAddress

Name: $userName
Phone: $userPhone''';
  }
}
```

### 8.5 Order Filtering Logic
```dart
// Backend: seller.routes.ts
router.get('/:sellerId/orders', authMiddleware, async (req, res) => {
  const { status, dateFrom, dateTo, customerName, minPrice, maxPrice } = req.query;
  
  const filters: any = { sellerId: req.params.sellerId };
  
  if (status && status !== 'all') filters.status = status;
  if (dateFrom || dateTo) {
    filters.createdAt = {};
    if (dateFrom) filters.createdAt.$gte = new Date(dateFrom);
    if (dateTo) filters.createdAt.$lte = new Date(dateTo);
  }
  if (customerName) filters['deliveryAddress.name'] = new RegExp(customerName, 'i');
  if (minPrice || maxPrice) {
    filters.totalPrice = {};
    if (minPrice) filters.totalPrice.$gte = parseFloat(minPrice);
    if (maxPrice) filters.totalPrice.$lte = parseFloat(maxPrice);
  }
  
  const orders = await Order.find(filters).sort({ createdAt: -1 });
  res.json({ success: true, data: orders });
});
```
